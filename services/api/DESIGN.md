# API 设计说明

## 职责

统一 API 是小程序和管理后台访问业务数据的唯一入口，集中处理身份权限、比赛与报名规则、队员资料、结果读取和充值流水。前端不直接连接数据库，也不各自重复实现业务校验。

## 数据模型

- `members`：队员身份、球衣信息、联系方式、个人介绍、头像/视频、统计和账户余额。
- `matches`：比赛时间地点、报名截止、名额、图片/视频、报名名单和可选比分。
- `charges`：管理员登记的金额、队员、日期、备注和创建时间。
- `authUsers`：账号 ID、队员 ID 与角色。演示数据包含一位管理员和队员演示账号。
- `media`：开发期文件存本地 `.data/uploads`，业务记录只保存 URL；生产应存腾讯云 COS。

完成比赛中的报名名单用于统计出勤，不另设签到确认记录。

## API 边界

- `/api/auth`：本地演示登录和当前会话查询；微信登录交换接口待配置。
- `/api/matches`：比赛浏览、报名/取消报名和已公布结果。
- `/api/members`、`/api/leaderboard`、`/api/me`：公开档案、出勤榜与当前队员私有资料。
- `/api/admin`：比赛创建、队员资料管理、媒体上传和充值流水。
- Repository 接口隔离本地 JSON 和 PostgreSQL，业务路由不依赖某种存储驱动。

公开队员资料不包含手机号、余额或充值明细。队员可以读取自己的私有资料；管理员可管理全队。

## 业务状态

比赛状态为 `upcoming`、`live`、`completed`。只有未开始、未截止且仍有名额的比赛可以报名；取消报名需在截止时间前完成。结果只有 `published` 为真时才返回比分。

充值是管理员手工登记的账户流水，不是微信支付交易。

## 正式环境待办

当前微信登录接口返回未配置响应，线上媒体上传也尚未接入 COS。正式开放前需接入微信身份交换/手机号授权，配置安全的 Token 密钥、CORS 来源、PostgreSQL 备份和网络访问，并完成 COS 文件上传。
